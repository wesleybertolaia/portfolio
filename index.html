DentalDesk

Help a prospective patient decide whether to request a dental visit.

Open booking site Open offer variant Source code

Friction to investigate

A prospective patient may hesitate if they have to share details before seeing what they can book or what happens after submitting.

Design and build

The Angular flow reveals a visit type, sample times, and a review in sequence. It explains when a clinic would confirm the visit and keeps the selected options when patients go back.

What I’d test

Compare a request-first offer with a time-first offer. Keep the flow constant and measure submitted requests per eligible session. Watch for a drop from time selection to review and, in a live service, check that requests turn into confirmed visits.

ShiftLedger

Help an employee record their first valid shift and a manager verify the hours.

Open time trackerSource code

Friction to investigate

A first-time user may be unsure how to enter a break or what counts as a valid shift. A manager needs to see the saved entry and understand how the total was calculated.

Design and build

The React interface explains the inputs and offers editable sample hours before saving. It rejects overlapping shifts and invalid durations. The manager view reflects the saved entry and shows totals after filtering.

What I’d test

Compare guided entry with the same form starting blank. Measure valid first saves per new employee session. Check time to save, validation errors, and accidental acceptance of example values.

Evidence. Both projects use fictional data. In a mobile browser check, DentalDesk preserved the selected visit and time when going back. In ShiftLedger, saving the 90-minute example updated the manager’s total from 24h 30m to 26h. Conversion tests with real traffic are proposed.
